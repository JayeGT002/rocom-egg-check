# 项目简述

## 项目定位

「蛋查查 · Rocom Egg Check」是一个面向洛克王国玩家的桌面工具，用于按精灵蛋的重量档位、蛋组、属性、名称或图鉴编号查询精灵，并推演子代体重百分比的迭代结果。产品重点是快速查找和清楚呈现数据，不是游戏客户端或在线服务。

## 当前功能

- **精灵蛋尺寸查询**：输入精灵名称、图鉴编号或精灵蛋重量（kg），筛选 1–10 档范围、蛋组和属性；多个蛋组或属性之间按“任一匹配”，不同筛选类别之间按“同时满足”。蛋重反查只返回蛋重区间包含该数值的初始形态，并在卡片轨道上标出该重量位置。文字搜索也可通过进化链名称找到该链的初始形态；纯数字搜索按三位图鉴编号精确匹配。
- **结果卡片**：展示精灵头像、编号、名称、初始形态属性、蛋组、蛋重区间和档位。档位筛选和属性筛选以每条进化链的初始形态数据为准。蛋重数据的单位是克，界面显示为千克，并以静态轨道表示迷你蛋与巨大蛋区间。
- **收藏与快捷查询**：结果卡片可收藏精灵，侧栏在有收藏时提供“只看收藏”过滤；最近 5 条有效查询条件自动记录，可一键恢复或清空。结果区支持按默认顺序、图鉴编号、名称、档位和蛋重区间排序。收藏、最近查询和排序偏好只保存在本机浏览器存储，不参与设置页的 JSON 导入导出；加载数据时会移除已不存在的收藏 id。
- **子代计算器**：根据父本、母本体重百分比，推演固定一方繁育时逐代平均体重及达到“大块头（>98%）”或“小不点（<2%）”的代数。可录入每代实测值和可选声音值，并保存、重命名、更新和管理计算记录。
- **设置与用户数据**：提供全局 UI 缩放、系统字体选项、计算记录 JSON 导入导出和关于页面。偏好及计算记录保存在本机浏览器存储中。

## 技术结构

| 路径 | 职责 |
| --- | --- |
| `main.go` | Go / MyGo 桌面入口；嵌入精灵数据并提供类型化查询绑定。 |
| `window-icon.png` | 嵌入 Go 程序的 64×64 窗口图标，通过 `SetIcon` 用于 Linux 和 Windows 标题栏与任务栏；macOS 不设置窗口图标。 |
| `data/pets.json` | 应用运行时读取的精灵及蛋重数据。 |
| `ui-draft/src/App.jsx` | 查询页、结果卡片、主导航及设置页面。 |
| `ui-draft/src/OffspringCalculator.jsx` | 子代计算器、迭代计算结果和记录管理。 |
| `ui-draft/src/styles.css` | 页面布局、响应式规则和应用定制样式。 |
| `ui-draft/src/colors.js` | 蛋组色、属性色和档位色。 |
| `ui-draft/src/mygo.ts` | 前端使用的 MyGo 类型化绑定。 |
| `ui-draft/src/devEggData.js` | 普通浏览器开发预览使用的数据适配器；正式桌面运行由 Go 绑定提供查询。 |
| `mygo.config.ts` | MyGo 的前端目录、命令、图标和构建输出配置。 |
| `DATA-LICENSES.md`、`ui-draft/THIRD-PARTY-NOTICES.md` | 数据、图片、配色和第三方组件的来源与许可记录。 |

前端使用 React、Vite 和 `rocokingdom-ui`。正式桌面应用由 MyGo 承载 WebView，Go 负责提供查询数据；Vite 开发预览使用本地适配器。

## 开发与打包

- 根目录 `npm run dev` 启动 MyGo 桌面开发环境；`npm run dev:web` 启动普通浏览器预览。
- 根目录 `npm run build` 调用 MyGo 构建桌面应用；`npm run build:web` 单独构建前端。
- Go 代码通过 `//go:embed data/pets.json` 明确嵌入数据文件。MyGo 前端产物目录配置为 `ui-draft/dist`。
- `devdoc/` 是供开发者和 agent 阅读的源代码资料，位于前端项目目录之外，不属于 `frontendDist`，也没有被 Go 嵌入。不要将这些文档复制到 `ui-draft/public/` 或运行时资源目录。

## Agent 工作提示

1. 开始任务前阅读 `devdoc/` 下的项目文档，再查看目标组件及其调用方；文档概述用途，实际实现和交互以当前代码为准。
2. 开发过程中及时维护受改动影响的文档，并按[文档阅读与维护流程](agent-workflow.md)核对更新。
3. 如果改动筛选、蛋重或子代算法，保持字段单位、边界条件和用户可见文案一致，并检查相关说明是否需要同步。
4. 新增或替换数据、图片、配色、字体及第三方组件时，先核对现有许可记录，并按要求补充来源。
5. 该项目已有未提交改动时，保留它们；不要覆盖与当前任务无关的工作。
6. 开发过程中不要擅自添加多余的说明性文字，包括代码注释、文档段落和界面描述；只有用户明确要求或许可时才添加。实现功能所必需的标签、错误提示和无障碍名称应保持最少且准确。
